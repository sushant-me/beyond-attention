# beyond-attention

A selective state-space model — **Mamba's S6 recurrence** — implemented from
scratch, with the mathematics checked three independent ways, and a
parameter-matched comparison against a Transformer on a task where the two are
*expected* to differ.

## What this is, and what it is not

**It is** a working, tested, dependency-light implementation of a non-attention
sequence model, plus an honest measurement of it. Every number below is
generated from a machine-readable results file by `experiments/render_readme.py`
and can be regenerated by anyone with a CPU and twenty minutes.

**It is not** a new architecture, and it is not better than a Transformer. The
recurrence here is Mamba's; the contribution is the correctness work and the
measurement, not the maths. Three claims that would be easy to make and would be
false:

* *"It replaces attention."* It does not. On the task below, attention wins, and
  the reason is structural rather than a tuning matter — see [Results](#results).
* *"It is faster because it is linear."* Asymptotically yes. **As implemented
  here, no** — the reference scan is dramatically slower than attention at every
  length measured, and the section on that is the most useful part of this
  README.
* *"It is a new model."* It is S6, written out longhand so it can be tested.

The interesting content is the third of those: a linear-time algorithm whose
constant factor is so large that it loses at the sizes people actually run. That
is a real engineering problem, it is visible only by measuring, and it is
described honestly rather than hidden behind the asymptotic claim.

## The recurrence

A state-space model keeps a fixed-size state `h` and updates it as it reads:

```
a_t = exp(delta_t * A)                    # (B, L, D, N), in (0, 1)
b_t = delta_t * B_t * x_t                 # (B, L, D, N)
h_t = a_t * h_{t-1} + b_t                 # (B, D, N),  h_{-1} = 0
y_t = sum_n C_t[n] * h_t[d, n]            # (B, L, D)
```

`A` is stored in log space and negated, so every decay is in `(0, 1)` and the
recurrence is stable for *any* parameter value the optimiser picks. `delta`, `B`
and `C` are produced from the input, which is what makes the scan **selective**:
the model chooses per token how much to write into the state, how much to decay
it, and what to read back. A non-selective SSM uses constants for those three and
cannot do content-based lookup at all — that single difference is the reason this
architecture can retrieve an association instead of just smoothing.

The cost is linear in sequence length and the state is a fixed size, so the
memory a model needs does not grow with the context it has read. That is the
genuine structural property. Whether it is worth anything at a given scale is an
empirical question, which is the point of the measurements.

## Correctness

The recurrence is simple enough to get subtly wrong, and the usual way that
survives is that a fast path is compared only against a loss curve — which
descends happily for a model that is quietly forgetting everything past its chunk
boundary. So there are three implementations that share no code:

| function | method | role |
|---|---|---|
| `selective_scan_reference` | explicit loop over time | the definition |
| `selective_scan_chunked` | short loop per chunk, then scan the summaries | what a kernel does |
| `selective_scan_associative` | Hillis-Steele scan over the `(a, b)` monoid | log₂(L) parallel steps, no sequential dependence |

and the tests assert they are **equal to float64 tolerance** on random,
degenerate and adversarial inputs, at chunk sizes that do and do not divide the
sequence length, with gradients matching between the loop and the chunked path.

Two properties are tested independently of that, because numerical agreement
cannot catch them:

* **Causality.** Change an input at position `t` and require every output before
  `t` to be bit-for-bit unchanged — for every path, at chunk sizes strictly
  smaller than the cut. This caught two real bugs in my own work: the test's
  parametrisation never included the chunked path at all, and a reversed chunk
  scan (a genuine future leak) passed it before that was fixed.
* **Long-range propagation.** The depthwise convolution has a kernel of 2, so
  position 0 reaches positions 0 and 1 and nothing else. A test changes only
  position 0 and requires the output at position 11 to move: if it does not, the
  block is a local filter wearing a state-space model's name.

Every test was mutation-checked — the algorithm was deliberately broken in five
ways and each break had to fail a specific test. Breaking the monoid in the
associative scan, dropping the carry between chunks, reversing the chunk scan,
removing the convolution's causal padding and removing the attention mask each
fail different tests; the records are in the commit history.

## Results

Both architectures: same data, same optimiser, same learning-rate schedule, same
step budget, same seed, and parameter counts printed so the budgets can be
checked. The task is **multi-query associative recall** — a sequence of key/value
pairs, then a query key, and the model must emit the paired value. Keys and values
are drawn from disjoint halves of the vocabulary, so a model cannot score by
predicting a likely token; it has to have stored the association and retrieve it.

MQAR is the right test because it is *exact* (accuracy, not a loss to interpret)
and *position-invariant* (so a Transformer with no positional encoding is a fair
baseline rather than a crippled one). It is also the case where a fixed-size
state should struggle, since recalling one of many associations requires
superposing them, while attention can address any position directly. That is a
falsifiable prediction and this harness exists to test it, not to confirm it.

## Why the linear-time model is not faster here

This is the part worth reading.

Attention is O(L²) in sequence length and this is O(L), so the textbook
expectation is that the state-space model pulls ahead at long sequences. Measured
on this implementation, the opposite happens at every length tested, and the
reasons are specific rather than mysterious:

1. **The scan materialises its terms.** The chunked path builds `a` and `b` at
   shape `(B, L, D, N)` — with `d_inner = 128` and `N = 16`, that is 2048 floats
   per token per layer before any autograd bookkeeping, and autograd then saves
   several such tensors for the backward pass. A production kernel never
   materialises them: it streams through the chunks holding only the running
   state. The memory advantage of a state-space model is a property of a *fused*
   kernel, not of the recurrence on its own.
2. **The chunk loop is Python.** The recurrence inside each chunk runs as a
   Python-level loop of `chunk` iterations. That is what makes it readable and
   what makes it slow.
3. **The state does not shrink at small scale.** `d_state = 16` per channel is
   not small in absolute terms, so at the lengths where attention's quadratic
   term is still negligible, the state-space model is paying for a fixed-size
   state that is bigger than the attention matrix it is competing with.

So the honest summary is: **the asymptotic argument is correct and this
implementation does not benefit from it.** The comparison at these sizes is
dominated by constant factors, and closing that gap requires writing a fused
selective-scan kernel — `mamba-ssm`'s CUDA implementation, or a chunked
TorchScript/C++ version — not tuning the model. That is future work, and until it
exists any claim that this code is faster than attention would be false.

## Reproducing this

```bash
uv venv && uv pip install --index-url https://download.pytorch.org/whl/cpu torch
uv pip install -e . pytest

python -m pytest tests/ -q                    # correctness
python experiments/run.py --out results.json  # measurements (CPU, ~20 min)
python experiments/render_readme.py results.json README.md   # rewrite the tables
```

`experiments/run.py --help` has the knobs; `--steps`, `--seeds` and `--pairs`
are the ones that cost time.

## Limitations, stated rather than discovered later

* **This is not a language model.** The task is synthetic, the vocabulary is 17
  tokens, and nothing here says anything about language modelling quality.
* **Two layers and `d_model = 64`.** Both models are far too small to separate
  "cannot do it" from "needs more capacity", so a low number means *this* model
  at *this* size did not learn it, not that the architecture cannot.
* **One task.** MQAR tests associative recall. It says nothing about the many
  things attention is bad at, or about length extrapolation, streaming inference,
  or throughput on hardware where a fused kernel exists.
* **CPU only.** No CUDA was available, so nothing here reflects GPU throughput,
  where the memory-bandwidth contract is entirely different and where selective
  scan kernels are designed to run.
* **The scaling measurement is peak-RSS growth** over a post-import baseline, in
  a fresh process per point. It is a real measurement of this implementation, not
  an allocator-accurate profile.
