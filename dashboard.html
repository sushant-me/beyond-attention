The voiced/unvoiced control, drawn rather than asserted

Two signals through the same framing and the same autocorrelation decision: a block of white noise and a 220 Hz tone of the same length. The curve is the estimator's own normalised autocorrelation peak — the number the voiced/unvoiced decision was made on — so what is drawn is the decision variable, not a summary of it. The dashed line is the 0.45 threshold; the band along the floor marks the frames the decision called voiced.

White noise keeps its largest confidence at 0.1643 against a threshold of 0.45, and is judged voiced in 0.000 of frames; the tone sits near 0.817 and is voiced in 1.000 of them. The tone's estimated pitch is 221.6 Hz for the 220 Hz asked for — a 0.73% error, inside the 2% the tests assert; the search band in the module is 60–400 Hz, which is wider than the range it works over. A detector that answered "voiced" to everything would pass every tone test ever written and would make every pitch number on this page meaningless, which is why the noise case is on the page and not only in a table.

Over the noise draws summarised in voice-affect.json, the largest voiced ratio is 0.000 and the largest confidence 0.1396. The probe above is one further draw from its own seed stream, so it could not shift those numbers. Framing: 16,000 Hz, 198 frames of 25 ms every 10 ms.

Agent: one task, decision by decision

The loop reads the task's instructions as structured events, streams them through the recurrence, decodes the state into the registers carry, observations, op, arg, arg2, miss, kind, instructions, and calls one of add, mul, sub, lookup, remember, fetch, finish. Each step below shows what the state held when the choice was made, the call that came out of it, the observation the tool returned, and the carried value the next decision then read — so the operand chain is visible rather than claimed.

Results, and the controls that decide what they mean

The solve rate is a number about the person who wrote the tasks unless the controls are published next to it. They are, including the one that costs the increment its most flattering reading.

scalar_carry — the same controller with the carried value in one Python int instead of the state — reproduces the agent's rate in 35 of the 36 cells it shares with the agent. The cells where it does not (1): selective@6 (agent 1.000 vs control 0.320). So the control ties the agent everywhere except selective.

fixed_decay — a state of the same width with a constant, input-independent write gate: every value-carrying event goes into every slot — reproduces the agent's rate in 35 of the 36 cells it shares with the agent. The cells where it does not (1): selective@6 (agent 1.000 vs control 0.200). So the control ties the agent everywhere except selective.

no_memory — the state is wiped before every decision, and only the current instruction is re-streamed — reproduces the agent's rate in 21 of the 36 cells it shares with the agent. The cells where it does not (15): one_op@2 (agent 1.000 vs control 0.000), one_op@3 (agent 1.000 vs control 0.000), one_op@4 (agent 1.000 vs control 0.000), one_op@5 (agent 1.000 vs control 0.000), one_op@6 (agent 1.000 vs control 0.000), two_op@3 (agent 1.000 vs control 0.000), and 9 more cells, all listed in the control's own grid below. The families where they part: branch, lookup, one_op, selective, two_op.

random_action — tools and arguments drawn uniformly; the floor, not a policy — reproduces the agent's rate in 0 of the 6 cells it shares with the agent. The cells where it does not (6): literal@6 (agent 1.000 vs control 0.001), one_op@6 (agent 1.000 vs control 0.001), two_op@6 (agent 1.000 vs control 0.003), branch@6 (agent 1.000 vs control 0.003), lookup@6 (agent 1.000 vs control 0.006), selective@6 (agent 1.000 vs control 0.003). The families where they part: branch, literal, lookup, one_op, selective, two_op.

The same table says why the width is not the explanation: a state of the same width with a constant write gate (fixed_decay) reaches 0.200 on selective@6 where the agent reaches 1.000 — it is the gating, not the number of slots. The single-register memory fails selectively rather than at random: of 50 selective tasks it solves 16, and 16 of them asked for the key that was stored last. The correspondence holds task for task (True over 50 tasks).

What this page does not show

The same pattern the README uses, because the failure mode is the same: a page of generated numbers is persuasive whether or not the numbers mean what a glance says they mean.

It is not an emotion recogniser, and it is not a learning result. Three claims that would be easy to make from this page, and are all false:

  • "The descriptors identify emotion in speech." They identify which of 4 synthetic conditions generated a signal. Every utterance was synthesised by this repository, one parameter tuple per condition (neutral = F0 target 150 Hz, swing 0.01, jitter 0.01, amplitude spread 0.03, 2 bursts/s; aroused = F0 target 225 Hz, swing 0.12, jitter 0.05, amplitude spread 0.45, 5 bursts/s; subdued = F0 target 110 Hz, swing 0.004, jitter 0.01, amplitude spread 0.05, 1 burst/s; unsteady = F0 target 255 Hz, swing 0.15, jitter 0.1, amplitude spread 0.15, 3.5 bursts/s), and the labels come from the generator rather than from a listener. No human voice was involved at any point, there is no labelled affect corpus here to validate against, and the 0.969 accuracy is the recovery of synthetic parameters — not emotion.
  • "The loop learns, or something here was trained." Nothing on this page is in a gradient path: there is no optimiser, no loss and no backward pass anywhere in the agent code. The controller is hand-written branching, the recurrence's decay and its read/write gate are constants chosen by hand, and a seed only decides which tasks are generated. The voice descriptors are analytic measurements of a waveform, not learned features, and the encoder that bridges them to the model is a fixed random projection with no bias and no nonlinearity.
  • "The agent generalises." It runs one controller over a closed tool set (add, mul, sub, lookup, remember, fetch, finish) and a closed task family (literal, one_op, two_op, branch, lookup, selective), emitted by a seeded generator over bounded integers. The "task text" is that instruction grammar delivered as structured events: there is no tokenizer, no parsing and no language understanding anywhere in the path. The solver cannot be asked for a task the generator does not generate or a tool the registry does not hold, so a rate of 1.000 says the controller matches the shapes it was written against and nothing wider.

And the boundaries that a reader should carry away with the numbers:

  • No generalisation beyond the closed task family. Every task comes from the generator's own constraints, and those constraints are what make the controls interpretable. Nothing here speaks to a task outside the family.
  • The affect descriptors are synthetic-parameter recovery, not human emotion, and there is no real-speech validation. There is no corpus, no listener labels and no trained classifier; the conditions were built to differ along exactly the axes the descriptors measure, so the separation on this page is partly a property of the design.
  • The F0 numbers are bounded by the estimator, not by the signal. The module's 60–400 Hz band is a search range, not a working range: with the 25 ms window used here the tests assert a 2% tolerance at 150, 220 and 300 Hz and nothing below about 100 Hz. An unchanged clause from the README, repeated here because the chart makes the estimate look more authoritative than it is.
  • Jitter and speaking rate are frame-level proxies. Jitter is a successive-frame pitch difference between adjacent voiced frames and is bounded below by the 10 ms hop; "speaking rate" counts voiced segments and cannot see unvoiced consonants at all. Neither is a phonetics measurement.
  • The charts are averages of generated signals at one seed. Each F0 line is the mean over that condition's utterances, so it shows the shared burst structure and not the spread within the condition — the descriptor table is where the spread lives.
  • This page adds no measurements. It draws the numbers in the two JSON files. Its own arithmetic is axis scaling, percentages, and the comparison of each control's cells against the agent's; it fits nothing, infers nothing and estimates nothing.
  • Only the controls that were run are shown, and only at the budgets that were run. A missing cell in a control grid is a measurement that was not taken, printed as an em dash rather than filled in. Random action was measured at budget 6 only.
  • The selective family's advantage is narrow and its gate is hand-set. The gated state reaches 1.000 on selective@6 while a fixed, input-independent decay of the same width reaches 0.200 and one Python int reaches 0.320 — but the gate is chosen, not learned, the family is closed and synthetic, and the arithmetic families are unaffected, which is why the scalar-carry control still ties the agent there.
  • The page is only as fresh as its last render. Changing a results file without re-running the renderer leaves this page describing an older run; tests/test_dashboard.py fails if the committed page and the committed results files disagree, which is the point of publishing a generated surface.
